- **版本**: v1.0
- **日期**: 2026-08-15
- **状态**: 已确认（本 session 需求澄清结论的沉淀）

## 1. 项目背景与定位

用户在服务器上日常使用 Claude Code（CLI）完成编程与助理工作，但 CLI 只能坐在终端前用。刀鱼要做的只有一件事：

> **把微信变成 Claude Code 的遥控器。**

用户在微信里发消息，消息被转发给服务器上以 headless 模式运行的 Claude Code；Claude Code 的回答与执行进度实时回到微信。用户由此获得一部手机随时可用的、具备完整能力的编程 Agent 与日常助理。

**产品名**：刀鱼 (daoyu)。默认工作仓库 `~/proj/daoyu`（刀鱼自身代码也在其中，自举/dogfood）。

## 2. 目标用户

**仅产品作者本人（单用户）**。不做多租户、不做鉴权体系、不做计费。白名单机制仅用于防止陌生微信账号误触。

## 3. 产品目标与成功指标

| 目标 | 成功指标 |
|---|---|
| 微信端响应快 | 收到消息后 ≤2 秒收到 ACK 回执；本地命令 ≤1 秒返回结果 |
| 不丢信息 | 入站消息零丢失（落盘 + 去重 + at-least-once）；出站发送失败自动重试，超限进死信并告警 |
| 命令体验与 CLI 一致 | 微信中使用的斜杠命令与 Claude Code CLI 语法完全相同，只有一套命令体系 |
| 手机上完成真实开发工作 | review、重构、调试、跑测试等任务全程在微信内完成 |

## 4. 用户场景与故事

- **场景 A – 随地遥控编程**：用户在外面，微信发 `/review`，Claude Code 对 daoyu 仓库做代码审查，进度分段推到微信，报告最终完整送达。
- **场景 B – 浏览器操作**：用户发"打开 example.com 截屏，提取文字"，Claude 通过 MCP 操控浏览器、截屏、OCR，文字结果回到微信。
- **场景 C – 危险操作审批**：strict 模式下 Claude 要跑 shell 命令，微信收到"允许执行 `pytest`？Y/N"，用户回复 Y 后继续。
- **场景 D – 长任务托管**：用户发一个大重构任务后不再盯着；任务在后台执行，用户随时 `/tasks` 查进度、`/cancel` 取消。
- **场景 E – 配置调优**：用户微信发 `/model sonnet`、`/permissions`、`/config` 等，像在 CLI 里一样查询与修改配置。

## 5. 功能需求

### FR-1 微信对话
通过个人微信号与 Claude Code 自然语言多轮对话，上下文跨消息、跨进程重启保持。

### FR-2 统一斜杠命令系统（核心）
微信里的命令与 Claude Code CLI **同一套语法、同一个命名空间**，不发明第二套。命令分三种执行方式，对用户透明：

1. **转发**：headless 可执行的官方命令（`/review` `/compact` `/model` `/effort` `/context` `/usage` `/init`、superpowers 全套、自定义 `.claude/commands/*`）原样交给 Claude Code 执行。
2. **代理**：TUI 交互专属命令（`/permissions` `/hooks` `/plugins` 等需开对话框的）由刀鱼拦截，以相同命令名与参数格式操作同一底层配置，输出文字版结果。
3. **桥命令**（仅 5 个，CLI 中无对应物——替代键盘操作）：`/cancel`（替代 Ctrl+C）、`/tasks`（查看运行中/排队任务）、`/status`（系统整体状态）、`/cd <目录>`（切换工作目录=切换会话）、`/policy <档>`（替代 shift+tab 切权限档位）。

另有继承自 ClawBot 库的 **iLink 运维命令**（与 Claude 无关，管连接本身）：`/time`（连接剩余时间）、`/重新连接`。

`/help` 动态生成，列出当前实际可用命令（从 Claude 的 `system/init` 事件同步），永远与真实能力一致。

### FR-3 会话管理
每个"用户 ↔ 工作目录"对绑定一个持久 Claude 会话（UUID）；`/cd` 切目录即切会话；历史会话可查、可恢复；`/adopt` 可收养终端（TUI）创建的会话为微信话题——微信与服务器终端可交叉接续同一话题；`/delete` 可删话题（连同其任务）或单删任务记录（回 Y 确认，防误删）。

### FR-4 软件开发能力
在真实仓库上：读写代码、执行 shell、git 操作、代码审查（`/review` `/code-review` `/security-review`）、特性开发（`/feature-dev` 及 architect/explorer/reviewer 子代理）、TDD、superpowers 工作流全套（brainstorming → writing-plans → executing-plans → finishing-branch 等）。

### FR-5 MCP 能力（"像我一样"）
默认装载：

| MCP server | 能力 |
|---|---|
| chrome-devtools | 操控浏览器：导航/点击/填表/执行 JS/网络抓包/**截屏**/性能分析（Linux 服务器经 runner 注入 headless Chrome——SPA 渲染可达，2026-08-19 实证） |
| daoyu-ocr（RapidOCR 本地封装） | 从图片提取文字（中英混识，本地推理，runner 恒注入的系统条目） |
| web-reader | 抓取阅读网页 |
| context7 | 实时查库文档 |
| playwright（钉版 `@playwright/mcp`，Linux 复用 chrome-headless-shell） | 浏览器自动化备选（2026-08-20 装载，默认启用，`/mcp off playwright` 可关） |

`/mcp` 命令管理（列表/启用/禁用/新增），改动下一条消息即生效。

### FR-6 权限与安全策略
四档 `/policy`，微信随时切换：

| 档位 | 行为 |
|---|---|
| `auto`（默认） | 仓库内增/删/改/执行、仓库外操作、shell 全部自动执行 |
| `strict` | 仓内编辑自动；shell 与仓外操作推送到微信审批（Y/N） |
| `bypass` | bypassPermissions，无任何提示 |
| `plan` | 只分析不改动 |

**恒定安全网（任何档位都生效）**：
- 硬 deny 清单（`/`、`/etc`、`~/.ssh`、`~/.claude`、刀鱼数据库等灾难路径），微信可增删（bypass 档下另以工具级拒绝兜底，生效性以实测为准）；
- 预算闸（每任务 turn 数与美元上限），与权限档位独立、恒生效。

### FR-7 配置管理
- **会话级**：`/model` `/effort` `/compact` `/context` `/usage` 等转发官方命令，即时生效。
- **持久级**：`/config` `/permissions` `/mcp` 等代理命令修改刀鱼专属配置文件，下次调用生效；配置版本化、可审计、可回滚。

### FR-8 进度反馈与长任务
- 收到消息秒回 "✅ 收到，处理中"，同时显示微信"正在输入"状态；
- Claude 流式产出按节流（约 2~3 秒、合并）推送到微信，避免刷屏；超长回复自动分页；
- 超长任务（dev server、大重构）转后台执行，不阻塞新消息；`/tasks` 查进度、`/cancel` 取消。

### FR-9 可靠性（不丢信息）
- 入站：先落盘再处理，按 `msg_id` 去重；
- 任务：at-least-once 投递 + 幂等执行 + 崩溃后自动恢复重跑；
- 出站：发件箱模式，失败自动重试，超限进死信并告警；
- 进程重启自动回放未完成任务与未投递消息。

### FR-10 状态查询
`/status`（系统整体状态：队列深度、死信数、当日费用、今日已发送条数、连接剩余时间）、`/tasks`（任务列表）、`/time`（iLink 连接剩余时间）。

## 6. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | ACK 延迟：正常网络下 ≤2s；本地命令 ≤1s |
| NFR-2 | 入站消息零丢失；出站至少重试 5 次后才进死信 |
| NFR-3 | 单服务器、单用户部署，systemd 托管，运维动作少且可脚本化 |
| NFR-4 | secret（API key、token）不进 git、不进日志明文 |
| NFR-5 | 成本可控：每任务预算上限硬性生效 |
| NFR-6 | 出站节流与每日上限（微信侧风控防护） |
| NFR-7 | 微信适配层可替换（ClawBot ↔ 其它方案），更换不影响后端 |

## 7. 范围外（明确不做 / 二期）

- **图片已实现（M3）**：微信发图即对话；Claude 经 `send_image` 工具回图（ClawBot CDN 加密收发），截图原图发送由此可用（真机验收状态见 §9）。
- **二期**：语音/文件/视频收发。
- **不做**：多用户、群聊、鉴权/计费体系、Web 管理界面。

## 8. 风险与约束

| 风险 | 影响 | 缓解 |
|---|---|---|
| ClawBot 为腾讯新开放能力，无 SLA，可变更/终止 | 微信通道可能失效 | 适配层接口抽象，可替换为 wxauto/企业微信等 |
| iLink token 失效需人工确认（协议无免扫码路径） | 低频（实证 >2.6 天，主动续期 30 天） | 失效自动检测（errcode -14 / HTTP 401 双路）→ ⚠️ + 二维码链接推微信，点链接确认即恢复 |
| ClawBot 媒体通道仅图片可用（M3，CDN 加密收发） | 语音/文件/视频发不了 | 图片走 CDN 加密通道；其余形态二期再评估 |
| 腾讯保留内容过滤/限速权利 | 消息可能被限 | 出站节流、内容拟人化、熔断暂停 |
| Claude API 成本 | 失控烧钱 | 预算闸 + `/usage` 可查 |
| agent 拥有 shell，误操作风险 | 数据损失 | 预算闸恒生效 + deny 兜底（bypass 下工具级拒绝）+（strict）微信审批 |

## 9. 里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M1 – MVP** | ClawBot 收发 + SQLite 队列 + headless 对话 + 会话持久 + 统一命令（转发/代理/桥命令）+ 可靠性全套 | 微信多轮对话不丢消息；`/review` 全流程跑通；重启进程任务自动恢复 |
| **M2 – 完全体** | 审批 MCP（strict）+ 长任务后台（`--bg`）+ MCP 全家桶（浏览器/截屏/OCR）+ 配置命令全套 + `/policy` 四档 | 全部 FR 覆盖；场景 A–E 全部走通 |
| **M3 – 二期** | 媒体收发（图片双向：发图即对话、Claude `send_image` 回图）、截图原图发送 | 微信收到 Claude 发的原图——已真机验收通过（2026-08-19，spec §5 五项全过） |
